本项目实际行为由通用算法、可替换的追踪器与 [Agent 协议](AGENT_PROTOCOL.md) 控制。后续评估应使用多段干净原片及独立 C 位时间标注，对比明确判定区间的正确率、漏判、错判、切换延迟和处理倍速；不能仅优化“未知时间更少”。

2026-10-21 补查：[Deep SORT 原项目](https://github.com/nwojke/deep_sort) 将外观描述与运动关联结合；[论文](https://arxiv.org/abs/1703.07402)提供相应研究依据。此项目借鉴“外观与运动互补、候选歧义应拒绝”的一般方法，未引入它的代码、TensorFlow 依赖或人物重识别权重。新实现仅比较肩髋之间服装颜色与粗图案，不提取面部特征。它是可关闭、可撤销的匿名关联实验，不能把行人数据集的结果当成统一舞台服装下的成员识别能力。NEON 的 5 组服装匹配只做了服装裁剪目视检查，尚无独立人物身份真值。

## 人物连续性算法复核

用户要求把人物识别算法搞清楚，核心仍是跨镜头保持人物对应、姓名和 C 位时间，而非只把模块接通。以下是实际代码审计、同一视频缓存复现和官方实现复核的结果。新增诊断已经运行；下述模型升级方案尚未实现。

### 算法分别解决什么

| 层次 | 输入与输出 | 本项目状态 |
|---|---|---|
| 检测与姿态 | 一帧图像 → 人物框、关键点 | RTMO-s 已运行；框错或漏检会影响后续所有层 |
| 镜头内追踪 | 连续检测 + 运动历史 → 局部轨迹 ID | OC-SORT 已运行；ID 只代表局部轨迹，遮挡可能断裂或错接 |
| 跨片段关联 | 多帧外观、时间、同屏约束 → 推测连续组 | 当前只有手工服装描述，不能当作可靠的长期人物记忆 |
| 姓名对应 | 明确指向该人物的来源标注 → 姓名及有效区间 | 已有证据接口；候选名单和演唱字幕不能完成对应，实际绑定仍为 0 |
| C 位选择 | 当前画面的队形、姿态、景别与时序 → 当前主位 | 规则基线，不需要等姓名；统计再查询关联和姓名映射 |

ReID 通常学习把目标图像变成向量，使同一目标更接近、不同目标更远；输出是相似性而非真实姓名。追踪 ID、外观组、真实姓名是三种不同的信息。将编号永久保存，只保存了已有判断；无法修复之前的误关联。

本项目可继续实现非面部外观与运动驱动的匿名连续性，以及来源明确的人物标注。这里不设计或实现从人脸检索真实姓名的流程，也不让 Agent 根据脸图或整队名单猜测对应关系。姓名不能由“更强的追踪器”凭空产生。

### 为什么舞台不能直接套行人追踪

[DanceTrack 论文](https://arxiv.org/abs/2111.14690)正是研究相似外观、多样动作与强关节运动下的多目标追踪。作者指出，依赖可区分外观的既有方法在群舞场景明显退步。该数据集能检验匿名目标关联，不能验证真实姓名或舞台 C 位。

对本项目的推论：同服装多人交叉时应减少对外观的依赖；切镜后旧画面的位置和速度通常不可直接比较。镜头内需要运动与可靠外观互补，跨镜头需要独立的片段关联与拒绝机制。若遮挡或切镜前后没有足够区分证据，延长等待也不能保证唯一解。

### 对用户视频的实际诊断

使用 NEON 原有完整检测缓存，223.5666667 秒、2236 个 10 fps 样本、51 个镜头；三种追踪器走同一个正式 `AnalysisPipeline`、C 位 v4 和首帧确认逻辑。没有重新解码或推理，也没有上传视频。

| 同缓存回放 | 原始轨迹 | 观测时间中位数 | ≤10 次观测的轨迹 | 服装推测组 / 涉及轨迹 | 未判定 C 位时间 |
|---|---:|---:|---:|---:|---:|
| OC-SORT | 549 | 1.2 秒 | 244 | 5 / 10 | 79.7 秒 |
| ByteTrack | 557 | 1.4 秒 | 218 | 2 / 4 | 86.5 秒 |
| CBIoU | 524 | 1.3 秒 | 194 | 4 / 8 | 80.7 秒 |

观测时间是实际有框的时间区间之和，不把消失间隙算进去。少编号、少未知或更多合并均不证明更准确；没有身份真值，所以脚本不输出 IDF1、ID switches 或准确率。当前仍保留 OC-SORT 默认值。

原始检测共 10,879 次，有效服装描述 6,894 次（63.37%）。这里按每帧每个检测计数，不能解释为识别了 63.37% 的成员。追踪器过滤后，467 条轨迹有至少一次服装入库，379 条达到三次；仍有足够长或清楚的片段可以研究更强表征。

OC-SORT 的关联诊断：2,270 次达到图库准备条件的匹配尝试中，1,886 次距离超阈值，186 次候选差距不足，112 次无合法候选，81 次等待更多投票，5 次合并。83.08% 因距离拒绝并不等于同人漏配率；其中可能本来就是不同的人。它说明不能在没有标签验证时单纯放宽距离阈值。

代码中另有两个结构限制：所有同镜头片段都被排除，不能修复同镜头遮挡造成的碎片；候选只看最近 12 秒，不能找回更早离场者。原图库固定可减轻污染，但也无法学习新的视角。单个镜头最多产生 31 条轨迹，而这些镜头的同时可见轨迹峰值分别为 9 和 6；这暴露了碎片负担，不证明具体哪次 ID 对应错误。

OC-SORT 缓存回放约 6.405 秒，其中服装关联约 4.539 秒；其余两种回放约 9.438 / 7.038 秒。诊断计时含计数开销且后台负载未隔离，**不含检测、解码、服装裁剪、OCR 或浏览器**，不能与全片实时速度混用。此次默认回放的 2236 帧及 10 条关联记录与上轮实际任务完全一致。

### 建议采用的结构与验收顺序

这是下一步实现方案，尚未作为完成的功能上线：

1. 保留快速 C 位路径。检测、同镜头追踪、C 位判定和视频时间轴独立推进；缺名字仍可准确地表达该框对应的主位区间。先测检测框质量和局部追踪，不能指望后面的关联修复错误框。
2. 增加高质量轨迹片段，而非对每一帧独立匹配。每条片段收集多次清晰、无头部污染的服装观测；同镜头结合运动，交叉和遮挡时允许暂不决定。不能把所有相似服装都视为同人。
3. 在片段层做带排他约束的全局匹配。保持独立、可撤销的关联图和版本；同时出现的不同目标不能合并。跨切镜不延续旧位置预测。长期图库需要多视角可靠样本、污染隔离、拒绝和撤销，不只是把 max_gap 改成无穷。
4. 在缓存与冻结测试片段上比较轻量服装编码器与当前颜色基线，再决定是否替换。用同一检测器、同一采样率；将已看过并调参的 NEON 作为开发集，另留干净视频作独立验收。需要标注同一匿名目标的轨迹对应，不需要用真实姓名来算关联质量。
5. 姓名是独立且有依据的属性。来源明确的人物标注按原轨迹和时间记录；推测关联不自动传播姓名。Agent 可批量检索和回填来源，但没有明确对应时，不能以完整名单代替证据。累计时间保留原始片段，在映射修订后重算，避免误合并长期污染排行。

轻量编码器优先做间隔采样、质量门控和批处理；例如九个目标每秒各提取两次特征，是 18 个裁剪，而每个分析帧都提取则为 90 个。这只是调度预算示例，不是已测速结论。切镜和低置信度时可以提高频率，稳定期间降低频率；不能降低 C 位更新时间来掩盖耗时。

上次完整流水线 203.321 秒处理 223.567 秒视频，约 1.10×，平均每个 10 fps 样本约 90.9 ms，距离 100 ms 的平均播放预算只余约 9.1 ms。这不是每帧最坏延迟保证；增加模型前必须重测分段速度、首次等待和整片缓冲暂停。10 秒初始缓冲只能吸收短暂波动，不能让长期低于 1× 的处理永远实时。完整分析后播放允许全局回溯，但同样不能凭空补足人物证据。

替换默认算法的验收应同时看：匿名关联 IDF1 / AssA、错误合并与拒绝、切镜后的恢复时间，以及独立标注的 C 位区间正确率和累计时长误差。功能目标不变；目前只有可复现的诊断，不宣称长期人物识别或真实姓名已解决。

### 复现诊断

```sh
uv run python scripts/audit_tracking.py DETECTION_CACHE OUTPUT_DIR --duration VIDEO_DURATION --tracker all
```

缓存需包含 `scripts/enrich_detections.py` 生成的 `garments` 才能诊断服装覆盖；缺少该字段时报告 null，不伪装成 0% 覆盖。输出含输入 SHA-256、配置、各层计数、镜头统计、逐帧结果与关联。默认正式运行不开启诊断计数。本次证据为本地忽略目录 `evidence/iteration7/audit.json`。
